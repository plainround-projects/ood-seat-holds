# The `mvnw` shell script, line by line

## What it is

`mvnw` is a text file of about 300 lines that your computer runs as a program. It is written in the **POSIX shell language**, the same language you type at a terminal prompt. A **shell** is a program that reads a command, runs it, and reads the next one; a **shell script** is a file that holds many such commands so you can run them all with one name. The file was generated by the Apache Maven Wrapper project (version 3.3.4) and copied into this repository unchanged. Its one job: make sure the right Maven is on the machine, then hand your command over to it.

`maven-wrapper.md` explains the idea and the settings file. This note reads the script itself, every line, because the script is part of the repository and a reader should be able to see that nothing in it is magic.

## Why this repository uses it

The repository promises that a reader needs only a JDK (Java Development Kit: the Java compiler and runtime) and `make`. The `Makefile` and the `Dockerfile` run `./mvnw`, never `mvn`. That works on a machine with no Maven because this script downloads the one Maven version the repository pins (3.9.16), keeps it in a cache folder, and starts it. Reading the script shows how that is done safely: it checks its inputs, it downloads into a temporary folder, it cleans up after itself, and it can verify a checksum.

## How it works underneath

You need a few ideas first. Each is explained here once, and the line-by-line section below uses them.

- **A program, a process, and arguments.** A program is a file. When you run it, the operating system starts a **process**: one running copy with its own memory. `./mvnw verify -q` starts a process of the shell, which reads `mvnw`; the words after the name (`verify`, `-q`) are the **arguments**, which the script sees as `$1`, `$2`, and all together as `"$@"`.
- **The shebang.** If a file starts with `#!` followed by a path, the operating system runs that program and gives it the file. `#!/bin/sh` means "run this file with the shell at `/bin/sh`".
- **Exit status.** Every command, when it ends, reports a number: **0 means success, anything else means failure**. The shell remembers the last one in `$?`. `if`, `&&` and `||` decide by this number. The command `true` always succeeds and `false` always fails; the command `:` does nothing and succeeds.
- **Variables and expansion.** `name=value` stores text (no spaces around `=`). `$name` or `${name}` is replaced by the stored text; the replacement is called **expansion**. Quoting with `"..."` keeps the result as one word even when it contains spaces. Single quotes `'...'` stop all expansion.
- **Parameter expansion tricks** (little editing operations inside `${...}`). They are used all through this script:
  - `${x-}` means "the value of x, or nothing if x is unset" (needed because the script turns on a rule that makes an unset variable an error).
  - `${x:-fallback}` means "the value of x, or `fallback` if x is unset or empty".
  - `${x:+word}` means "`word` if x is set and not empty, otherwise nothing".
  - `${x#pattern}` removes the **shortest** match of `pattern` from the **start** of x; `${x##pattern}` removes the **longest** match. `${x%pattern}` and `${x%%pattern}` do the same from the **end**. In a pattern `*` matches any text and `?` matches exactly one character.
- **Command substitution.** `$(command)` runs the command and is replaced by what it printed. `$(( ... ))` is arithmetic and is replaced by the number.
- **Test brackets.** `[ ... ]` is a command that checks a condition and reports success or failure. `-n "$x"` is true when the text is not empty, `-z` when it is empty, `-d` when the path is a folder, `-f` a regular file, `-x` an executable file, `!` negates, `=` and `!=` compare text.
- **`&&` and `||`.** `A && B` runs B only if A succeeded. `A || B` runs B only if A failed. So `[ -z "$x" ] || something` reads "unless x is empty, do something".
- **Standard output and standard error.** A process has two output channels: **stdout** (normal output) and **stderr** (messages about problems). `>&2` sends a message to stderr; `>/dev/null` throws output away; `2>/dev/null` throws away only the error channel.
- **Functions.** `name() { commands; }` defines a reusable group of commands. Inside, `$1` is the function's first argument. `return 1` leaves the function with a failure status.
- **`case`.** `case word in pattern) commands ;; pattern2) ... ;; esac` runs the commands of the first pattern that matches. `*` is the "anything else" pattern; `|` separates alternatives.
- **`exec`.** `exec program args` **replaces** the current process with the program. Nothing after it runs. The program's exit status becomes the script's. That is how `mvnw` ends: it turns itself into Maven.
- **`trap`.** `trap command SIGNALS` asks the shell to run the command when a signal arrives or the script ends. A **signal** is a message the operating system sends a process: `HUP` (the terminal closed), `INT` (you pressed Ctrl+C), `TERM` (a polite request to stop), and the shell's own pseudo-signal `EXIT` (the script is ending for any reason).
- **Here-document.** `cat >file <<END` followed by lines and a line `END` writes those lines into `file`. With `<<-END`, leading tab characters are removed from each line first, so the text can be indented in the script.
- **Wildcards (globbing).** `*` in an unquoted word expands to matching file names. The script turns this off with `set -f` and on again only where it needs it.

### Lines 44 to 79: `set_java_home`, finding a Java

This function runs only when the script has no `wget` or `curl` and must compile a small Java program to download Maven. Here it is in three pieces.

**Lines 44 to 61**

```sh

set_java_home() {
  # For Cygwin and MinGW, ensure paths are in Unix format before anything is touched
  if [ -n "${JAVA_HOME-}" ]; then
    if [ -x "$JAVA_HOME/jre/sh/java" ]; then
      # IBM's JDK on AIX uses strange locations for the executables
      JAVACMD="$JAVA_HOME/jre/sh/java"
      JAVACCMD="$JAVA_HOME/jre/sh/javac"

      JAVACMD="$JAVA_HOME/bin/java"
      JAVACCMD="$JAVA_HOME/bin/javac"

      if [ ! -x "$JAVACMD" ] || [ ! -x "$JAVACCMD" ]; then
        echo "The JAVA_HOME environment variable is not defined correctly, so mvnw cannot run." >&2
        echo "JAVA_HOME is set to \"$JAVA_HOME\", but \"\$JAVA_HOME/bin/java\" or \"\$JAVA_HOME/bin/javac\" does not exist." >&2

      fi
    fi
```

- Line 47: if `JAVA_HOME` is set and not empty, look inside it.
- Line 48: `-x` tests for an executable file. Some IBM JDKs on the AIX operating system keep `java` at `jre/sh/java`; if that file exists, lines 50 and 51 use it.
- Lines 52 to 54: the normal case, `$JAVA_HOME/bin/java` and `$JAVA_HOME/bin/javac`.
- Line 56: if either is not an executable file, lines 57 and 58 print a two-line explanation to stderr (`>&2`). Inside double quotes `\"` prints a quote mark and `\$` prints a dollar sign instead of expanding. Line 59 `return 1` leaves the function with failure.

**Lines 62 to 72**

When `JAVA_HOME` is not set, ask the shell where `java` and `javac` are. `command -v java` prints the full path of `java` if it is on your `PATH` (the list of folders the shell searches for programs) and fails otherwise. ### Lines 81 to 106: small helper functions

**Lines 81 to 90: `hash_string`**

```sh
# hash string like Java String::hashCode
hash_string() {
  str="${1:-}" h=0
  while [ -n "$str" ]; do
    char="${str%"${str#?}"}"
    h=$(((h * 31 + $(LC_CTYPE=C printf %d "'$char")) % 4294967296))
    str="${str#?}"
  done
  printf %x\\n $h
}
```

A **hash** is a number computed from text so that the same text always gives the same number and different texts almost always give different numbers. This function copies Java's `String.hashCode()` rule so the cache folder name is the same as in other Maven wrapper implementations. The rule: start with 0; for each character, multiply the running number by 31 and add the character's code; keep it within 32 bits.

- Line 83: `str="${1:-}"` stores the first argument; `h=0` starts the number (two assignments on one line).
- Line 84: loop while `str` is not empty.
- Line 85: `${str#?}` is the text without its first character; `${str%"..."}` then removes that rest from the end, which leaves just the first character. It is stored in `char`.
- Line 86: `printf %d "'$char"` is a `printf` trick: a number written as a quote mark followed by a character means "the character's code". `LC_CTYPE=C` makes the code a plain byte value. `$(( ... ))` does the arithmetic: `h * 31 + code`, and `% 4294967296` (that is 2 to the power 32) keeps the remainder so the number stays within 32 bits.
- Line 87: drop the first character from `str`, so the loop moves on. Line 88 ends the loop.
- Line 89: `printf %x\\n $h` prints the number in hexadecimal (`%x`) and a line break. The function's output is that text.

**Lines 92 and 93: `verbose`**

Line 92 defines `verbose` as doing nothing (`:` is a command that does nothing and succeeds). Line 93 replaces it with a version that prints its first argument, but only when `MVNW_VERBOSE` is `true`. So the rest of the script can call `verbose "message"` freely.

**Lines 100 to 106: `trim`**

```sh
trim() {
  # MWRAPPER-139:
  #   Trims trailing and leading whitespace, carriage returns, tabs, and linefeeds.
  #   Needed for removing poorly interpreted newline sequences when running in more
  #   exotic environments such as mingw bash on Windows.
  printf "%s" "${1}" | tr -d '[:space:]'
}
```

Lines 101 to 104 are a comment: the change request `MWRAPPER-139` was a bug where a Windows-style line ending (a carriage return character before the line break) stayed attached to a value read from a file. `tr -d '[:space:]'` deletes every space, tab, carriage return and line break from the text it receives through the **pipe** `|` (a pipe connects the output of the left command to the input of the right one). `printf "%s" "${1}"` prints the argument without adding a line break.

## Mistakes people make

- **Editing the file by hand.** It is generated; a fix belongs in a regenerated copy (`mvn wrapper:wrapper`), not in a local edit that the next upgrade overwrites.
- **Running it with a different shell and expecting bash features.** It is written for plain `sh`, so it avoids bash-only syntax; if you add bash-only syntax it can break on Debian-based systems where `/bin/sh` is `dash`.
- **Forgetting to quote `"$@"`.** Without quotes, an argument with a space (`-Dname="a b"`) would split into two. The script quotes it everywhere.
- **Removing `set -e` to "make errors go away".** Then a failed download would be followed by an attempt to unpack a missing file.
- **Blaming the wrapper for a Maven error.** After line 295 the wrapper is gone; the process is Maven. Errors after that point belong to Maven, the project, or a plugin.

## Check yourself

1. *What does the first line do?* It tells the operating system to run the file with `/bin/sh`.
2. *What do `-e`, `-u` and `-f` in `set -euf` do?* Stop at the first failure, treat an unset variable as an error, and disable wildcard expansion.
3. *Which line decides which Maven is used?* Line 112 to 118 read `distributionUrl` from the settings file; line 136 chooses the command `mvn`; line 146 builds the cache folder.
4. *Why does `mvnw` end with `exec`?* It replaces the script with Maven, so there is one process and Maven's exit status is the script's.
5. *What does `trap clean HUP INT TERM EXIT` guarantee?* The temporary download folder is deleted when the script is interrupted or finishes, whatever the reason.
